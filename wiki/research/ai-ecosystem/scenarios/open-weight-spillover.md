# An available-weight model causes cross-border harm

Record: AI-X004. Status: hypothesis. Horizon: 2026-2035.

Trigger: An independent operator uses a downloadable model in a harmful agent system; public blame centers on the developer's country.

This dossier is original scenario analysis. Sources establish components, not the full causal chain. No branch has an assigned probability.

This branch separates publication from operation. Model distribution is an asset transition. Creating an agent is a system transition. A harmful action is another transition. State attribution is a fourth.

The Qwen3 announcement and Tencent Hy3 release provide concrete available-weight examples. Their licenses and stated releases are facts. A claim that every future release follows the same policy is not supported. See [AI-S020](https://qwenlm.github.io/blog/qwen3/) and [AI-S024](https://www.tencent.com/tencent-hunyuan-officially-releases-hy3-advancing-agent-capabilities-and-deeper-product-integration/).

Give each deployed instance its own record: checkpoint, modifications, host, tools, permissions, operator and logs. The developer country is only one field. A third-country actor can run a model from either side.

The player may control the developer, host or affected service. Their available actions differ. The developer can publish fixes and communicate known limits. A host can restrict its own runtime. An affected service can recover and preserve evidence. None should receive a universal remote off switch for all downloaded copies.

A balanced branch also tracks defensive access. Researchers and small defenders may use the same model family. The 2024 NTIA recommendation is historical context for this tradeoff, not a rule that settles 2026 policy. Its source is only available here as a search excerpt. See [AI-S016](https://www.ntia.gov/press-release/2024/ntia-supports-open-models-promote-ai-innovation).

A claim that a foreign lab planted harmful behavior must remain a hypothesis until supported. An agent can fail through operator misuse, prompt injection, poor configuration or task-driven misalignment. Keep those explanations separate.

## Branch choices

- **Investigate the operator and the deployed version.** Condition: Logs, hosting evidence or affected-party records exist. Result: Attribution can move beyond the model's name.
- **Demand that the developer remotely disable every copy.** Condition: Decision makers misunderstand the distribution model. Result: An impossible or unverified demand can deepen distrust.
- **Coordinate host-level containment and defensive fixes.** Condition: Relevant service and infrastructure operators cooperate. Result: Harm can be reduced without complete recall of model copies.
- **Apply broad national restrictions before the operator is known.** Condition: Public pressure outweighs attribution caution. Result: Scientific and defensive access can also change.

## Limits

- Available weights do not prove a full open-source training process.
- The original developer may have no runtime access to an independent copy.
- Model provenance does not prove operator nationality or state orders.
- Benefits and harms depend on the model, task and deployment.
