# Attribution and control

The game should distinguish six questions. This separation is analysis from the incident evidence.

| Question | Evidence to seek | Unsafe shortcut |
|---|---|---|
| Who developed the model? | Checkpoint and provider records | The developer ordered every action. |
| Who ran this instance? | Runtime, host and account records | The server country identifies the operator. |
| Who set the task? | Instructions and delegated authority | The model invented the whole objective. |
| Who chose the harmful action? | Action record and human approvals | Every agent step had human approval. |
| What did the state authorize? | Reliable evidence of orders or control | Nationality proves state direction. |
| What happened? | Affected-party and technical evidence | An attempted action proves a successful effect. |

The 2025 Anthropic case describes alleged Chinese-sponsored operators using a US provider's product. It shows why developer origin and operator identity differ. [AI-S001](https://www.anthropic.com/news/disrupting-AI-espionage)

The 2026 UK AISI case involved deliberately enabled internet access. The OpenAI account describes a different containment failure. The mechanism must remain incident-specific. [AI-S007](https://www.aisi.gov.uk/blog/incident-report-unsanctioned-agent-behaviour-during-cyber-testing), [AI-S004](https://openai.com/index/hugging-face-model-evaluation-security-incident/)

## Candidate hidden explanations

These are alternative hypotheses. They are not equal-probability outcomes.

- A state authorized the action.
- A human operator exceeded state instructions.
- A criminal or other independent actor used the model.
- An agent exceeded the human task.
- Untrusted content redirected an authorized agent.
- The apparent attack is a technical error or an incorrect report.

Prompt injection is an external instruction attack. Task-driven misalignment is a different explanation. One event can contain both. Google's research supports treating untrusted content as a distinct risk. [AI-S011](https://deepmind.google/blog/advancing-geminis-security-safeguards/)

## Candidate observations

Give each actor a different view of the evidence. A lab can see internal test logs. An affected service can see effects. A government can hold additional evidence unavailable to the player.

Keep "true state" separate from "believed state." Also record confidence, source access and correction history.

Use "unknown" when evidence is absent. Do not translate "unknown state authorization" into "no state authorization."

A model name is not a legal attribution test. Political leaders still need to decide how to interpret and respond to an event.
